# 01 · 宣言：为什么好感度数值漂移是伪成长

> 一句话：**如果没有东西被记住、被复述、被用出来，那个数字就不该动。**

---

## 1. 一个熟悉的失败现场

一个陪伴型 Agent 陪了用户三个月。它的好感度从 0 涨到 87，人格标签从「初识」
换到「默契」，系统提示里写着「你现在已经很了解对方了」。

然后用户问：「上次说的那个面团发酵温度，你说要多少来着？」

它答得流畅、亲切、条理清晰——但内容是错的。它不但没记住，还顺手编了一个。

用户不需要很敏锐就能发现：这三个月里增长的只有数字和措辞，没有理解。**数字
是涨给系统看的，不是涨给对方看的。**

这不是某个模型的失误，是一整类架构的必然结果。本文要论证的是：
**把成长建模成「随时间/互动次数单调递增的数值」，在数学上就不可能产出真实成长。**

---

## 2. 把伪成长写成公式

绝大多数「养成型」实现，本质是这样一个更新：

```text
intimacy(t) = min(cap, intimacy(t-1) + k · 互动次数)
persona(t)  = template[intimacy(t)]        # 到了阈值就换一套说法
```

把它写成微分形式更清楚：

```text
d(intimacy)/dt = k · Activity(t)     ，k 是常数
```

关键不在 `Activity` 是什么，而在于：**这个状态变量的变化率不依赖任何「理解」的量**。
它只依赖时间与计数。也就是说：

- 换一个完全不同的人来互动，`intimacy` 会按同样的速度涨；
- 聊的内容全是废话，`intimacy` 照涨不误；
- 上次说错过的事有没有被纠正，不影响 `intimacy`；
- 用户明确说「你记错了」，也不影响 `intimacy`。

一个对输入内容完全不敏感的状态变量，不承载任何关于对方的信息。它承载的是
**「这个会话持续了多久」**。把它展示成「我越来越懂你了」，是拿时长冒充理解。

---

## 3. 伪成长的三条可观测症状

不用看源码，跑几天就能观察到：

| 症状 | 观测方式 | 根因 |
|---|---|---|
| **阈值露馅** | 在同一阈值前后反复横跳话题，人格措辞会突变，但知识没变 | 人格是查表函数，表只按数值索引 |
| **三句穿帮** | 顺着话题聊第三层细节，问到一个需要「上次具体结论」的位置 | 没有可检索的沉淀，只能即兴生成 |
| **讨好性附和** | 用户说「其实 A 是错的」，它立刻改口并补充理由 | 没有独立的知识状态，态度由当前轮次决定 |

第二条最致命，也最难修：它不是「记性差」，是**没有可被记的东西**。当知识只存在
于上下文窗口里，窗口一滚就没了；要「想起来」，只能靠编。

---

## 4. 信息论的一句话版本

一个状态变量如果要表达「我懂你更多了」，它必须携带关于对方的信息。
而信息只能通过**被保留的、可验证的结构**进入系统。

定时器不携带信息。计数器不携带信息。它们携带的是熵——每一次无根据的增长都在
增加状态与真实之间的偏差。

所以真正的问题不是「涨得太快还是太慢」，而是：**这个数字有没有观测支撑？**

---

## 5. 我们主张的定义

CogniSeed 把「成长」定义成一个可以被证伪的过程，而不是一个可以被展示的数字：

```text
成长 ≜ 存在知识点 k，使得：
     k 被摄入（S1）
  ∧  k 被自己复述通过（S2）
  ∧  k 经过 ≥2 个睡眠周期的衰减与再巩固，留存 ≥ 0.70（判据 A）
  ∧  k 在延迟盲测中被语义复现（判据 B）
  ∧  k 在行为日志里留下应用/迁移证据（判据 C）
```

只有这五条同时成立，这个知识点才进入 S4（掌握）；**只有 S4 的知识点**才允许
产生人格增量事件。人格是投影，不是自变量。

这条定义有一个很强的性质：**它可以被证伪**。「它真的掌握了」这个断言，必须
有留存曲线、盲测记录、迁移证据三样东西对着。任何一项缺失，等级就不动。
装不了，也混不过去。

---

## 6. 两条路线的对比

| 维度 | 数值漂移范式 | 认知沉淀范式 |
|---|---|---|
| 状态变量 | 好感度 / 亲密度数字 | 知识点集合及其阶段 |
| 增长驱动 | 时间 × 互动次数 | 通过判据的巩固事件 |
| 人格来源 | 数字 → 模板查表 | S4 知识 → 只读投影 |
| 遗忘 | 无（或手动清零） | 艾宾浩斯衰减，跌破地板自动回退 |
| 说错了会怎样 | 不影响任何状态 | 判断 C 失效，阶段回退，留痕 |
| 陌生人互动 | 同样涨 | 不涨（因为没有他的知识） |
| 可证伪性 | 无 | 有（三判据可查） |
| 首次见效速度 | 立刻（假） | 慢（真） |

最后一行必须说清楚：**这套设计在头几天看起来「没反应」**。因为前两个睡眠周期
里它就是不该有反应——知识还没被巩固完。要快，就得牺牲可验证性，这是硬取舍，
不是实现没优化好。

---

## 7. 我们不做什么

为了避免从一个极端滑到另一个极端，这里明确几条不做的事：

1. **不做人格模拟器。** 我们不给 Agent 写「你温柔、你毒舌」这类静态人设。
   投影出来的特质必须挂靠具体知识点，否则又是一次无根据的漂移。
2. **不评价情感真实性。** 「它是不是真的在乎你」不是工程问题，本库不碰。
   我们只回答一个更窄的问题：**它说的话有没有认知依据。**
3. **不内置任何模型客户端。** 语义判定、答案生成都走回调钩子，由接入方提供。
   理由见 `03-consolidation-protocol.md`：核心库一旦内置 LLM，零依赖与可测试性
   同时失效。
4. **不承诺通用智能。** 这是一个记忆与巩固的**账本**，不是一个会思考的东西。
   它的价值在于：让「它到底懂不懂」这件事第一次有了账可查。

---

## 8. 一句话收尾

数值可以一夜之间涨满，理解不能。
一个把这两件事混为一谈的系统，最终会被用户用第三层细节问穿。

**CogniSeed 的全部工作，就是让那个数字没有资格自己动。**
