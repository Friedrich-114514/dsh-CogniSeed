# 02 · 认知阶梯：S1 感知 → S4 掌握

> 四级不是四个标签，是四道闸门。每一道都要求证据，缺一条就停在原地。

---

## 1. 四级定义

| 阶段 | 名称 | 进入条件（代码里的 `Ladder.can_advance`） | 含义 |
|---|---|---|---|
| `S1` | 感知 | 摄入一条原子知识点，来源 ∈ {`agent_note`, `behavior_log`} | 见过了，但只是存了一条记录 |
| `S2` | 复述 | `restatements ≥ 1` 且至少一次 `passed` | 能用自己的话说出来 |
| `S3` | 巩固 | `sleep_cycles ≥ 1`（经历至少一次睡眠复核） | 进入巩固队列，正在被衰减与再巩固 |
| `S4` | 掌握 | 判据 A ∧ B ∧ C ∧ 变式练习（见 `03-consolidation-protocol.md`） | 跨周期仍能复现、且在行为里用出来了 |

只有 S4 允许触发人格增量事件（`PersonaDelta`），且同一节点只投影一次。

> 注意 S1 的措辞是「一条原子知识点」。粒度错了整套系统就废了：
> 「烹饪」不是知识点，「低温慢煮要把温度稳定在蛋白质变性区间」才是。
> 原子性决定了后面能不能盲测、能不能找到迁移证据。

---

## 2. 状态机

```text
        add_node(source ∈ {agent_note, behavior_log})
                 │
                 ▼
              ┌─────┐   restate(passed=True)   ┌─────┐
              │ S1  │ ───────────────────────► │ S2  │
              └─────┘                          └─────┘
                 ▲                                  │
                 │ 留存 < 地板                       │ sleep_cycles ≥ 1
                 │                                  ▼
              ┌─────┐       判定失败            ┌─────┐
              │ S2  │ ◄───────────────────────  │ S3  │
              └─────┘                           └─────┘
                                                   │
                                    A ∧ B ∧ C ∧ 变式  │
                                                   ▼
                                                ┌─────┐
                                                │ S4  │──► PersonaDelta（一次）
                                                └─────┘
                                                   │
                                            留存 < 地板（回退一级）
                                                   ▼
                                                ┌─────┐
                                                │ S3  │
                                                └─────┘
```

两条硬规则：

1. **一次只上一级。** 即使三判据一次全过，S1 也只能走到 S2。跳级会让「什么时候
   学会的」失去时间戳，而时间戳是判据 A 的基础。
2. **回退是单向的下移一级，不是清零。** 留存跌破 `demote_floor`（默认 0.45）时退回
   上一级重新巩固。知识还在，但「已掌握」的结论被撤销——因为它确实不成立了。

---

## 3. 为什么不能跳级：三判据各自防的是不同的事

很多人会问：既然最后要过三判据，为什么还要中间两级？

因为三判据测的是**三个不同的失败模式**，而且它们必须在不同时间点上测：

- **复述（S2）防「存了但没消化」。** 原样复制一句正确的句子，和真的理解，在
  存储层面完全一样。要求它换词复述，才能区分「存了」和「懂了」。
- **睡眠复核（S3）防「当场记住、隔夜就忘」。** 立即测试测的是工作记忆。间隔
  一整夜再测，测的才是长期记忆。这也是为什么 `blind_test_delay_hours` 是个
  参数而不是 0。
- **三判据（S4）防「能背但不会用」。** 背诵和迁移是两条神经通路。判据 C 要求
  行为日志里有应用痕迹，就是在要求那条通路也被点亮。

跳级等于把「消化」「隔夜」「应用」三件事压成一个瞬间判断，那三件事就全都测不到了。

## 4. 活跃池上限 5：认知负荷，不是性能限制

`SleepScheduleConfig.max_active_pool = 5`。

这不是数据库限制，是**注意力预算**。一个 Agent 同时深入五个领域已经很多了；
第六个领域进来时，最冷的那个被驱逐出池（`pool_evictions` 留痕）。

被驱逐不等于删除：
- 它的知识点还在学籍表里，仍会参与睡眠复核；
- 它只是不再获得偏置引擎的「在学池加成」（`BiasEngine` 里 ×1.25）；
- 它下次被触碰时可以重新入池，排到队首。

这条设计针对的是「什么都会一点、什么都不深」的摊大饼失败模式。约束在池子上，
比约束在输出上有效得多——**限制输入，比要求模型克制输出更可靠**。

---

## 5. 每日新增配额 2：为什么是「每天」不是「每轮」

`SleepScheduleConfig.daily_new_quota = 2`，按自然日（UTC）重置。

理由不在吞吐量，在**巩固带宽**。睡眠周期是按天结算的，如果一天往里塞 50 条，
那么下一次结算时每条的复核预算就被摊薄到接近于零——结果全是半成品。

配额是唯一能真正兑现「少量多次」的机制。它也很诚实地告诉接入方：**这个库不是
拿来批量灌知识图谱的**。它是拿来做「一天真正学会一两件事」的。

超额会抛 `QuotaExceeded`。注意去重发生在配额之前：重放同一条知识点不会白白吃掉
配额，这对事件重投（至少一次投递语义）是必要的。

## 6. 同心圆：领域热度是结果，不是设置

领域按**已掌握（S4）知识点数量**自动分层：

| 圈层 | 条件 | 偏置权重（`BiasEngine`） |
|---|---|---|
| 外圈 `OUTER` | 0 条 S4 | ×1.00 |
| 中圈 `MIDDLE` | 1–2 条 S4 | ×1.05 |
| 内圈 `INNER` | ≥ 3 条 S4 | ×1.15 |

关键点：**圈层不能手动设置**。它是 `registry.rings()` 算出来的投影。如果你能
直接给某个领域「设为内圈」，那它立刻退化成第二个好感度数字。

同心圆的意义是回答「它现在最懂什么」。这个答案必须由账本算出来，不能由配置写进去。

---

## 7. 与既有学习理论的对应

| 本库 | 对应概念 | 差异 |
|---|---|---|
| S1→S2 复述 | 提取练习（retrieval practice） | 要求换词，避免原样复读 |
| S3 睡眠复核 | 间隔重复（spaced repetition） | 稳定性随成功次数增长，不是固定间隔 |
| 判据 B 延迟盲测 | 延迟测验效应 | 强制延迟 ≥ `blind_test_delay_hours` |
| 判据 C 迁移 | 迁移适宜性（transfer） | 只认行为日志，不认自我报告 |
| 外/中/内圈 | 专长发展 | 由已掌握数量推出，不可手设 |

## 8. 代码映射

| 概念 | 模块 | 关键 API |
|---|---|---|
| 阶段枚举 | `cogniseed/models.py` | `Stage`（`IntEnum`，可比较可排序） |
| 闸门判定 | `cogniseed/ladder.py` | `Ladder.can_advance` / `Ladder.transition` |
| 三判据证据 | `cogniseed/ladder.py` | `PromotionEvidence`（`criterion_a/b/c`） |
| 单节点推进 | `cogniseed/consolidation.py` | `ConsolidationEngine.run_cycle` |
| 学籍与池 | `cogniseed/registry.py` | `LearningRegistry.add_node` / `.active_pool` |
| 圈层 | `cogniseed/registry.py` | `LearningRegistry.rings` |

`PromotionEvidence` 是纯数据对象：它不查库、不算留存，只负责回答
「这四条同时成立吗」。这样判据的语义只有一个地方定义，文档和代码不会各写一份。
